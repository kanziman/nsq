# multilingual — PRD (단일 진실 원천)

> `spec-fixed.md` 기반. **[GATE 2]·[GATE 3] 통과** — 사용자 상시 정책(추천안 자동 진행)에 따라 **A안(단일 파이프라인 내 모드 분기)** 확정, Out of Scope 확정.

## 1. 개요

대본 없는 다국어(우선 일본어) 유튜브 영상을 자동 자막(VTT)만으로 임포트하는 **자막 전용 모드**를 기존 임포트 파이프라인에 추가하고, `language('en'|'ja')` 속성을 축으로 문장 복원(sentence-builder)·번역 프롬프트·단어 하이라이트(Intl.Segmenter)·후리가나(`<ruby>`)·튜터 페르소나를 분기한다.

- **목표**: 일본어 영상을 URL+언어 선택만으로 임포트해, 기존 플레이어·스크립트 뷰·번역·튜터 전체 학습 루프를 일본어로 사용할 수 있다.
- **비목표(요약)**: 자동 언어 감지, Whisper ASR, 화자 분리, 인앱 사전 팝업, ja/en 외 언어 (상세 §4).

## 2. 사용자 스토리

1. 학습자로서, 공식 대본이 없는 일본어 영상도 **URL과 언어 선택만으로** 임포트해 쉐도잉을 시작하고 싶다.
2. 학습자로서, 파편화된 자동 자막이 아니라 **자연스러운 문장 단위**로 구간 반복·번역 학습을 하고 싶다.
3. 학습자로서, 한자 위 **후리가나**를 보며 따라 읽고, 모르는 **단어를 클릭해 사전**을 찾고 싶다.
4. 학습자로서, 일본어 에피소드에서는 튜터가 **조사·활용 같은 일본어 문법**을 한국어로 설명해 주길 바란다.

## 3. 기술 결정 (ADR) — **확정: A안 단일 파이프라인 내 모드 분기**

### 3-0. ADR (Architecture Decision Record)

- **Context**: 기존 파이프라인은 `download → subtitle(en 고정) → transcript → alignment(matchRate 게이트) → translation(en→ko 고정) → meta`로, transcriptUrl이 필수다. 대본이 없는 일본어 영상을 지원하려면 정합 없이 자막만으로 `segments.json`을 만들어야 하고, 이후 소비 계층(번역·표시·튜터)이 언어를 알아야 한다. `fetchSubtitle`은 이미 수동→자동 자막 폴백을 갖췄고(en 고정만 문제), `Segment.speaker`는 임의 문자열을 허용하며, 화자 필터는 세그먼트에서 파생(#115)된다.
- **Decision**: `runImportPipeline`에 **모드 분기**를 넣는다. 입력 계약을 `{ youtubeUrl, transcriptUrl?, language }`로 완화하고, `transcriptUrl` 부재 시 자막 전용 모드로 `download → subtitle(lang) → sentence-builder → translation(lang) → meta`를 실행한다. `sentence-builder`는 (1) 1차로 VTT 큐를 큐 세그먼트로 변환해 `segments.json`을 **먼저 기록**하고(폴백 확보), (2) LLM에 큐 배치를 보내 "큐 인덱스 그룹 + 복원 문장"을 회수해 문장 세그먼트로 재기록한다(best-effort·증분 저장). start/end는 그룹 첫/끝 큐 시각을 재사용한다. `language`는 `meta.json`·`ImportState`에 영속하고, translation·furigana·튜터·플레이어가 이를 읽어 분기한다. 상태에 `'building_sentences'`, RetryStep에 `'sentences'`를 추가한다. 후리가나는 translation과 동형의 best-effort 스텝(`furigana.ts`)으로 `Segment.ruby`를 주입한다.
- **Alternatives (기각)**:
  - **B안 의사 대본 생성 후 기존 정합 재사용**: LLM이 자막에서 대본 텍스트를 생성해 `transcript.txt`로 저장 → 기존 alignment 경로 통과. **기각 사유** — 같은 자막에서 나온 텍스트끼리 정합하므로 alignment·matchRate가 형식적 통과 의례가 되고(정보 이득 0), LLM이 자막 어휘를 조금만 바꿔도 anchor가 깨져 오히려 허위 실패를 만든다. 파이프라인 무분기라는 장점보다 "게이트가 거짓 신호를 낸다"는 비용이 크다.
  - **C안 별도 오케스트레이터(runSubtitleImportPipeline) 신설**: 자막 전용 전용 파이프라인 분리. **기각 사유** — 상태 기록(writeState)·재시도 아티팩트 검증·fire-and-forget 에러 정책·모니터 폴링 계약을 통째로 중복하게 된다. 두 파이프라인의 상태 스키마가 갈라지면 ImportMonitor도 이원화된다. 분기 2~3개를 피하려고 200줄 오케스트레이터를 복제하는 것은 역이득.
- **Consequences**:
  - **장점**: 상태·재시도·모니터·API 계약 단일 유지, 기존 en 경로 무변경(회귀 표면 최소), 큐 세그먼트 선기록으로 문장 복원 실패에도 학습 가능 산출 보장, 스텝(DI) 단위 TDD가 기존 translation 테스트와 동형.
  - **단점/한계**: (1) `runImportPipeline`의 조건 분기 수가 늘어나 오케스트레이터 복잡도 증가(runAlignment 류 플래그가 모드 축으로 확장). (2) 자막 전용 모드는 wordStarts·audioStart가 없어 단어 하이라이트가 균등분할 근사에 머문다. (3) 문장 복원 품질을 게이트하지 않으므로(무게이트) 어색한 문장 병합이 그대로 노출될 수 있다 — retryStep 'sentences'로 재실행하는 운영적 보완만 존재.

## 4. Out of Scope (이번 구현에서 명시적으로 배제)

1. **자동 언어 감지** — 언어는 임포트 폼에서 명시 선택. 감지 로직 없음.
2. **ja/en 외 언어** — `LanguageCode` union 확장 여지만 남기고 zh 등 미지원·미테스트.
3. **Whisper 등 ASR** — 자막이 전혀 없는 영상은 임포트 실패가 정답. 음성 인식 도입 없음.
4. **화자 분리(diarization)** — 자막 전용 모드는 단일 화자 `'SPEAKER'` 고정. 화자 추정 없음.
5. **인앱 사전 팝업** — 단어 클릭은 외부 사전(네이버) 새 탭까지만. 사전 API·팝업 UI는 `learning-dictionary` 태스크로 유보.
6. **kuromoji 등 형태소 사전 라이브러리** — 단어 분해는 `Intl.Segmenter`만. 품사 태깅·기본형 복원 없음.
7. **자동 자막 단어 시각 정밀 매핑(ja)** — `wordStarts` 생성 없음. 하이라이트는 균등분할 근사.
8. **문장 복원 품질 게이트/자동 채점** — matchRate 류 수치 게이트 없음(best-effort + 큐 폴백 + retryStep 재실행만).
9. **기존 en 에피소드 소급 마이그레이션** — `language` 부재 = `'en'` 간주로 충분. 파일 재작성 배치 없음.
10. **pitch accent·JLPT 레벨 표기 등 학습 메타** — 표시 확장 없음.
