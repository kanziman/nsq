# import-translation — 확정 요구사항 (spec-fixed)

> `spec-original.md` + 코드베이스 분석 + Stage 1 인터뷰로 확정. 본 문서가 PRD 이전 단계의 기준.
> **[GATE 1]** 사용자 승인 대기 중.

## 1. 한 줄 정의

임포트 파이프라인 정합(alignment) 성공 직후, `segments.json`의 영어 문장(`text`)을 **OpenRouter LLM**으로 한국어 번역하여 각 세그먼트의 `translation` 필드에 주입·영속화하는 **번역 스텝**을 추가한다.

## 2. 핵심 사용자 (Primary User)

- **직접 사용자**: 에피소드를 임포트하는 학습자 본인(관리자 1인 로컬 워크플로우).
- **가치**: 임포트만 하면 스크립트 뷰의 한국어 번역(blur/toggle, 이미 완성)이 자동으로 채워져, 별도 수작업 없이 한↔영 대조 학습이 가능해진다.

## 3. 확정된 결정 (Stage 1 인터뷰 결과)

| #   | 결정 항목         | 확정 내용                                                                               | 근거                                                                             |
| :-- | :---------------- | :-------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------- |
| D1  | **Provider**      | **OpenRouter LLM** (HTTP fetch 직접, SDK 미도입)                                        | CLAUDE.md의 OpenRouter 키 정책과 일치, 문맥·화자·구어체 반영, 프롬프트 제어 용이 |
| D2  | **실패 처리**     | **Best-effort** — 번역 실패해도 `status: completed` 유지, `translation`만 비움          | 번역은 학습 보조, 핵심(오디오·정합)은 이미 확보. meta 단계와 동일 정책           |
| D3  | **재시도·멱등성** | `RetryStep`에 `'translation'` 추가 + **이미 `translation` 있는 세그먼트는 스킵**        | 부분 실패분만 저비용 재보충, 전체 재번역 방지                                    |

## 5. 최소 동작 시나리오 (3)

1. **정상 임포트**: 신규 URL 임포트 → 정합 성공 → 번역 스텝이 `segments.json`의 모든 세그먼트에 `translation` 주입 → `completed`. 스크립트 뷰에 한국어(blur)가 채워짐.
2. **번역 재시도**: 이전 임포트에서 번역 일부 누락(LLM 오류) → `retryStep: 'translation'` 재접수 → `translation` 없는 세그먼트만 번역, 기존 번역 보존 → `completed`.
3. **번역 실패 완주**: OpenRouter 전면 오류 → 번역 스텝이 예외를 삼키고 `translation` 없이 → 임포트는 `completed`(오디오·정합·재생 정상). 사용자는 나중에 시나리오 2로 보충.

## 6. 경계 조건

- **빈/공백 text**: 번역 대상에서 제외(그대로 통과).
- **segments.json 부재/손상**: 번역 스텝 진입 불가 → best-effort로 스킵(정합이 선행 보장하므로 정상 흐름에선 발생 안 함).
- **부분 배치 실패**: 한 배치 실패가 다른 배치를 막지 않음(배치 독립).
- **중복 재실행**: 이미 번역된 세그먼트는 재호출하지 않음(멱등).
- **길이 불일치 응답**: 입력≠출력 개수면 그 배치 전체 스킵.
- **API 키 미설정**: 번역 스텝 즉시 no-op + 경고 로그, 임포트는 completed.

## 7. 예외 및 에러 처리 (UI 전달)

- 번역은 best-effort이므로 **실패를 사용자 에러로 노출하지 않는다**(모니터는 `translating` 진행만 표시, 이후 `completed`).
- 서버 로그(`console.error`)에는 실패 원인 기록.
- 번역이 비어도 ScriptView는 이미 `translation` 부재를 안전 처리(전역 토글·노드 미렌더). 회귀 없음.

## 8. 성능 제약

- 배치(B3)로 호출 수 최소화. 세그먼트 N개 → 약 `ceil(N/20)` 회 호출.
- OpenRouter 호출 타임아웃 상수화(예: 60s/요청), 파이프라인 fire-and-forget 특성상 전체 임포트 시간에만 영향(사용자 폴링 UX 유지).

## 9. 기존 UI/패턴 일관성

- **표시 UI 신규 없음** — ScriptView 번역 표시(blur/개별해제/전체토글)는 완성 상태. 본 기능은 **데이터 주입만** 담당.
- 스텝 모듈은 `src/lib/services/import/translation.ts`에 배치, `alignment.ts`와 동일한 파일·DI·에러 컨벤션 준수.

## 10. 향후 확장성 / 종속성

- **선행**: `import-alignment`(완료) — `segments.json`이 입력.
- **후행 소비**: `script-view-translation`(완료).
- **확장 여지(본 범위 밖)**: 번역 캐시, 용어집(glossary) 고정, 다국어, 문장 내 구(phrase) 정렬 번역.

## 11. 용어 정의 (Ubiquitous Language)

| 용어                            | 정의                                                                                                |
| :------------------------------ | :-------------------------------------------------------------------------------------------------- |
| **번역 스텝(translation step)** | 정합 후 `segments.json`의 `text`→`translation`을 채우는 파이프라인 단계. 함수 `translate(videoId)`. |
| **translation 필드**            | `Segment.translation?: string`. 한국어 번역문. 부재 가능(옵셔널).                                   |
| **best-effort**                 | 실패해도 상위 파이프라인을 실패시키지 않고 산출물 일부 누락을 허용하는 정책(meta 단계와 동일).      |
| **멱등 번역(idempotent)**       | 이미 `translation`이 있는 세그먼트는 재번역하지 않음. 재시도 시 누락분만 보충.                      |
| **배치(batch)**                 | 한 번의 LLM 호출로 함께 번역하는 인접 세그먼트 묶음(기본 20). 문맥 유지 단위.                       |
| **translating**                 | `ImportState.status`의 번역 진행 상태(기 정의, 본 기능에서 활성화).                                 |
